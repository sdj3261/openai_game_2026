# Codex Collaboration 기록

## 1. 개발 공개

**GAIA//2126: 살아있는 지구는 챌린지 기간에 새로 시작한 게임입니다.** 작업을 시작할 때 저장소에는 재사용할 수 있는 기존 게임 구현이 없었으며, 현재 게임 코드·디자인 시스템·시뮬레이션·문서·테스트·배포 설정은 이번 챌린지를 위해 새로 개발했습니다.

따라서 “기존 개발 프로젝트를 활용한 경우”에 해당하는 이전 기능은 없습니다. 외부 오픈소스 라이브러리는 각 패키지의 라이선스에 따라 사용하며, 게임의 규칙·데이터 모델·UI 구성·아트 방향은 본 프로젝트에서 작성했습니다.

## 2. 사람과 Codex의 역할

### 제작자(사람)가 결정한 것

- 문제의식: 최근의 심각한 온난화와 기후 위험을 플레이 가능한 경험으로 만들기
- 핵심 판타지: 지구 문명을 100년 동안 운영하며 인간 거주 한계를 넘지 않게 하기
- 핵심 장면: 정책의 결과로 사람들이 실제로 이동하고 도시가 성장하거나 무너지는 3D 지구
- 장르 방향: 문명 운영, 전염/확산형 시스템, 도시 시뮬레이션, 행성 전략의 장점을 결합하되 독자적인 플레이 만들기
- 기술 방향: React + TypeScript + Vite + Zustand, Babylon.js, Web Worker, TypedArray, IndexedDB
- 스케일 원칙: 개인 에이전트 대신 population cohort를 계산하고, 시각화는 대표 장면으로 압축하기
- 제품 우선순위: 완벽한 물리 모델보다 정책 하나의 10–30년 뒤 결과가 눈앞에서 극적으로 보이는 것

### Codex가 수행한 것

- 아이디어를 5년 단위의 관찰 → 정책 → 사건 → 진행 → 결과 루프로 구조화
- 기후 → 물/식량/경제 → 거주 가능성 → 코호트 이주 → 도시 상태의 데이터 흐름 구현
- 5,000셀 TypedArray 세계와 Dedicated Worker 메시지 프로토콜 설계
- 정책, 사건, 국가 전망, 다중 결말과 점수 모델 작성
- React HUD와 Babylon.js 전략 지구의 컴포넌트 구조 구현
- IndexedDB 자동 저장과 GitHub Pages 정적 배포 경로 구성
- 생존 연도와 종합 점수를 비교하는 `LOCAL DEMO` 결과 대시보드 및 선택형 `/leaderboard` 계약 설계
- 단위 테스트, 빌드 검사, 브라우저 플레이 점검 지원
- GDD, 기술 아키텍처, 제출 문안과 시연 스크립트 작성

Codex는 제작자의 목표와 우선순위를 대신 정한 것이 아니라, 명시된 방향을 빠르게 시제품으로 만들고 모순·성능 위험·심사 조건을 점검하는 협업 파트너로 사용했습니다.

## 3. 실제 협업 방식

### 3.1 기획을 실행 가능한 단위로 변환

초기 아이디어에는 기후, 인구, 경제, 식량, 에너지, 이주, 전쟁, 재난, 질병, 기술 등 매우 넓은 범위가 있었습니다. Codex와 함께 “심사위원이 직접 플레이하며 코어 재미를 느낄 수 있는가?”를 기준으로 범위를 정리했습니다.

```text
전체 지구 시스템 구상
  ↓
기후 → 자원 → 이주 → 도시 변화에 집중
  ↓
정책 최대 2개 + 세계 사건 1개 / 5년
  ↓
20턴으로 100년 완주 가능한 Challenge MVP
```

전쟁·감염병·고급 외교는 코어 연쇄가 검증된 뒤의 확장으로 남겼습니다. 이 범위 결정이 Playability를 지키는 가장 중요한 협업 결과였습니다.

### 3.2 병렬 에이전트 분업

독립적으로 진행할 수 있는 작업은 Codex 서브에이전트로 나누어 동시에 처리하고, 공유 작업 폴더에서 통합했습니다.

| 트랙 | 책임 | 통합 시 확인 사항 |
|---|---|---|
| 시뮬레이션 | Worker, TypedArray, 정책 연쇄, 코호트 이주, 테스트 | 결정론, 인구/코호트 보존, 메시지 소유권 |
| 3D/UI | Babylon.js 지구, HUD, 국가 탐색, 정책/사건 인터랙션 | 서브에이전트 시안을 바탕으로 주 에이전트가 통합; WebGPU/WebGL2, 접근성 확인 |
| 디자인/콘텐츠 | 아트 방향, 아이콘 체계, 정책·사건·결말 문안 | 일관된 톤, 원인/결과 가독성 |
| 문서/제출 | GDD, 아키텍처, 협업 기록, 제출·시연 문안 | 실제 구현과 일치, 200자 제한, 과학 고지 |
| 검증/배포 | 테스트·빌드·Pages·브라우저 스모크 체크 | 새 방문자 기준 즉시 실행, 404/콘솔 오류 |

같은 파일을 여러 에이전트가 동시에 수정하지 않도록 책임 경계를 두었습니다. 최종 통합 담당이 타입, 패키지, 빌드와 실제 브라우저 동작을 다시 확인합니다.

### 3.3 빠른 피드백 루프

Codex에는 큰 요청 한 번만 전달하지 않고 다음 반복을 사용했습니다.

1. 제작자가 플레이어 경험과 기술적 가설을 제시
2. Codex가 작은 구현 단위와 위험을 제안
3. 코드와 문서를 동시에 갱신
4. 테스트, 빌드, 브라우저 실행으로 결과 확인
5. 실제 화면에서 인과가 약한 부분을 콘텐츠/시각 피드백으로 보강

예를 들어 “100,000명을 모두 시뮬레이션하지 않는다”는 제작자 원칙은 Codex가 3개 코호트 TypedArray와 대표 이주 경로 패킹으로 구체화했습니다. “최근에 매우 더워진 현실을 반영한다”는 피드백은 2026년을 이미 온난화된 상태로 시작하고, 단일 연도 관측과 장기 임계값을 구분하는 과학 고지로 연결했습니다.

## 4. Codex가 특히 효과적이었던 지점

### 시스템 사이의 계약

React, Zustand, Babylon.js, Worker가 한 프로젝트에 들어가면 상태가 중복되기 쉽습니다. Codex를 사용해 Worker를 세계 상태의 계산 주체로, Zustand를 화면 조정자로, Babylon.js를 표현 계층으로 구분하고 메시지 타입을 공유했습니다.

### 반복 가능한 밸런싱

정책의 감축량만 손으로 맞추는 대신, 동일 입력의 결정론과 극단 경로 테스트를 설계했습니다. 이를 통해 “무조건 좋은 카드”와 “선택할 이유가 없는 카드”를 코드 수준에서 찾을 수 있게 했습니다.

### 심사 기준을 개발 기준으로 전환

- Playability → 백엔드 없는 정적 웹, 첫 턴 1분, 자동 저장
- Originality → 코호트 이주가 도시를 바꾸는 살아 있는 3D 지구
- Codex Collaboration → 기획 분해, 병렬 구현, 테스트/문서 동기화
- Release Potential → 로컬 결과 보드, 서버 재검증 가능한 순위 계약, 20k/100k 셀, WebGPU Compute, Hive 연계 로드맵
- Presentation → 3분 안에 원인과 결과가 보이는 고정 시연 동선

## 5. 새로 개발된 산출물

아래 항목은 모두 챌린지 기간 신규 작업이다.

- 게임 제목, 세계관, 핵심 루프, 100년 결말 구조
- 기후·자원·경제·인구 이동의 단순화 시뮬레이션
- population cohort와 셀 기반 데이터 모델
- 정책 카드, 세계 사건, 국가별 위험/기회 콘텐츠
- 3D 전략 지구, 도시 상태, 이주/재난 시각 언어
- React 대시보드와 게임 상태 관리
- Worker 프로토콜과 IndexedDB 저장
- localStorage 폴백 최종 순위표와 미래 Go/PostgreSQL 검증 계약
- 테스트 및 GitHub Pages 배포 자동화
- 게임 디자인, 기술 설계, 과학·윤리 고지, 제출 자료

## 6. 품질과 안전을 위한 검증

Codex가 생성한 결과를 그대로 제출하지 않고 다음을 확인합니다.

- `npm test`: 공식, 경계값, 결정론 회귀
- `npm run build`: TypeScript와 프로덕션 번들 확인
- 배포 URL 새로 접속: 캐시 없는 첫 로드와 첫 턴
- 20턴 완주: 결말과 다시 시작
- 저장 후 새로고침: IndexedDB 복구
- WebGPU/WebGL2: 두 렌더 경로 확인
- 네트워크/콘솔: 404와 런타임 오류 확인
- 문서 대 구현: 정책 수, 조작법, 링크, 신규 개발 공개 일치

- Vitest 2개 파일, 15개 테스트 통과
- ESLint 오류 0건, TypeScript 프로덕션 빌드 통과
- 브라우저에서 2026→2126의 20턴 완주, A 결말과 최종 통계 확인
- 2031년 자동 저장 후 새로고침하여 연도와 정책 레벨 복구 확인
- 완주 기록을 `LOCAL DEMO` 순위표에 제출하고 생존 연도→점수 정렬 확인
- 국가 검색 대한민국→캐나다와 코호트·위험 전망 갱신 확인
- 390×844 뷰포트에서 가로 오버플로 없음, 콘솔 오류 0건

## 7. 재현 가능한 협업 증거

심사·발표에서는 다음 자료를 함께 보여줄 수 있다.

- Git commit history: 기능 단위 변경과 통합 과정
- `docs/` 문서: 기획 결정과 기술 선택의 근거
- 테스트 코드: 시뮬레이션 불변조건과 회귀 확인
- Worker/TypedArray 타입: 아이디어가 실제 계산 구조로 바뀐 증거
- GitHub Actions 기록: 자동 빌드와 배포 결과
- Codex 대화/작업 기록: 제작자 피드백과 병렬 작업 지시

## 8. 발표용 20초 협업 설명

> 저는 “정책 때문에 사람이 이동하고 도시가 바뀌는 살아 있는 지구”라는 핵심 경험과 기술 방향을 정했습니다. Codex와는 이를 5,000셀·코호트 기반 Worker 시뮬레이션, Babylon.js 지구, React 대시보드로 분해했습니다. 서브에이전트가 시뮬레이션·3D/UI·문서·검증을 병렬로 진행했고, 저는 범위와 플레이 감각을 계속 판단했습니다. 이 저장소의 게임 구현은 챌린지 기간에 새로 개발했습니다.

## 9. 한계와 다음 협업 과제

Challenge MVP의 수치는 실제 정책 예측이 아니며, 국가·도시 다양성도 제한되어 있습니다. 다음 단계에서는 기후·도시 전문가 검토, 플레이테스트 로그, 접근성 사용자 테스트를 사람의 판단 과정에 추가하고, Codex는 시나리오 회귀 실행·성능 프로파일링·콘텐츠 편집 도구 제작에 활용할 계획입니다.
