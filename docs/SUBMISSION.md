## 2. 심사위원에게 보여줄 핵심

GAIA//2126의 차별점은 기후 지표를 올리고 내리는 대시보드가 아니라, **정책의 결과로 인구 코호트가 이동하고 그 이동이 다시 도시를 성장 또는 붕괴시키는 살아 있는 전략 지구**다.

```text
플레이어 정책
  → 배출·자연·신뢰·회복력 변화
  → 지역 기온·물·식량·경제 변화
  → 코호트별 이주 압력
  → 지구 위 이주 경로
  → 도시 성장·긴장·붕괴
  → 다음 정책의 새로운 비용
```

한 턴의 선택이 5년 뒤 숫자와 지구의 외형을 동시에 바꾸며, 20턴 뒤 서로 다른 2126년을 만든다.

## 3. 심사 기준 대응

### 01 Playability — 실제로 잘 작동하는가?

**제출 증거**

- 설치·계정 없이 URL에서 바로 실행하며 순위 API 없이도 완주 가능
- 정책 최대 2개 + 세계 사건 1개라는 명확한 한 턴 구조
- 2026–2126년 20턴, 결말과 점수까지 완결된 한 판
- 생존 연도 우선, 종합 점수 내림차순의 `LOCAL DEMO` 최종 순위표
- Web Worker가 시뮬레이션을 처리해 3D와 UI 반응성 유지
- WebGPU 우선, WebGL2 폴백
- IndexedDB 자동 저장, 새로고침 복구와 초기화
- 국가를 검색해 같은 세계 상태의 지역별 결과 비교

**심사 중 30초 증명**

정책 2개와 사건을 선택해 5년을 진행하고, 연도·기온·배출·국가 위험·이주/도시 상태가 함께 바뀌는 것을 보여준다.

### 02 Originality — 아이디어와 플레이가 독창적인가?

**핵심 독창성**

- 국가 하나를 키우는 게임이 아니라 100년짜리 지구 문명 전체를 운영
- 기후를 배경 효과가 아니라 식량·물·경제·주거·이주의 원인으로 사용
- 개인 에이전트 대신 연령 코호트의 성격 차이를 계산
- 모든 수천 개 이동을 렌더하지 않고 상위 경로와 도시 상태로 “숫자를 살아 있는 장면”으로 변환
- 감축만 높이면 끝나는 퍼즐이 아니라 자연, 신뢰, 경제, 적응, 정의의 트레이드오프
- 절망만 소비하지 않고 여러 형태의 생존·회복 결말을 제공

장르적 영감은 문명 운영·확산 시뮬레이션·도시 건설·행성 전략에서 받았지만, 플레이의 중심은 **기후 정책이 인간 이동과 도시 형태를 바꾸는 시각적 인과**다.

### 03 Codex Collaboration — Codex를 효과적으로 활용했는가?

**협업 증거**

- 제작자가 문제, 핵심 장면, 기술 방향과 범위 우선순위를 결정
- Codex가 아이디어를 타입·Worker 프로토콜·시뮬레이션 틱으로 변환
- 서브에이전트를 시뮬레이션, 3D/UI, 콘텐츠/문서, 검증으로 분리해 병렬 개발
- 테스트와 프로덕션 빌드로 생성 결과 검증
- GDD, 기술 아키텍처, commit history, Codex 작업 기록 공개
- 챌린지 기간 신규 개발 범위를 명확히 명기

상세 기록: [`CODEX_COLLABORATION.md`](./CODEX_COLLABORATION.md)

### 04 Release Potential — Hive를 통해 확장 가능한가?

**현재 제품 기반**

- 정적 싱글 플레이이므로 즉시 배포와 체험 가능
- 최종 대시보드에서 생존 연도 → 스튜어드십 종합 점수 순으로 로컬 기록 비교
- 최종 기온·자연·신뢰·회복력과 가장 많이 투자한 정책 전략 태그 표시
- `VITE_LEADERBOARD_API_URL`이 비어 있는 심사 빌드는 `LOCAL DEMO`와 브라우저 `localStorage` 폴백을 사용하며, 현재 라이브 공유 백엔드는 배포하지 않음
- 저장소에는 Cloudflare Worker+D1 `GET/POST /leaderboard`, migration과 재실행 검증 테스트가 구현되어 있으며 외부 서비스만 아직 미배포
- Worker는 v1 전체 턴 로그를 재실행해 최종 지표·점수·등급·전략 태그가 모두 일치한 기록만 `verified: true`로 저장
- 국가·정책·사건 데이터 중심 구조로 콘텐츠 추가 용이
- 세이브 버전과 Worker 프로토콜을 분리해 장기 업데이트 대비

**Hive 확장안**

- 주간 동일 시드 “지구 의회” 챌린지와 점수표
- 플레이 결과/2126년 지구 카드 공유
- 공동 감축 목표와 커뮤니티 시즌 이벤트
- 업적, 친구 경로 비교, 정책 조합 통계
- 제작자/교육 기관 시나리오 배포
- Worker+D1을 실제 배포한 뒤 Hive 인증 subject와 서명된 단회 season nonce 연결
- D1의 측정된 운영 한계를 넘을 때만 Go/PostgreSQL 이관 또는 Redis 캐시 검토

WebGPU Compute와 Rust/WASM은 출시 조건이 아니라, 20,000–100,000셀로 세계 해상도를 높일 때 선택적으로 도입한다.

### 05 Presentation — 게임과 개발 과정이 명확한가?

**발표 구조**

1. 최근 더워진 지구라는 문제를 10초 안에 제시
2. 정책 한 번으로 원인 → 인간 이동 → 도시 변화 시연
3. 반대 성격의 두 정책을 비교해 자유도와 트레이드오프 증명
4. 2126년 결말로 게임의 목표를 마무리
5. Worker/TypedArray/Codex 병렬 개발 다이어그램으로 과정 설명

숫자 표를 길게 읽지 않고, 지구 위 변화와 선택의 결과를 중심으로 발표한다.

## 4. 3분 시연 스크립트

- 감축 정책 하나와 정의/적응 정책 하나를 선택한다.

결과에서 지표 변화와 지구 색/도시 불빛의 변화를 가리킨다.

- 이주 아크 하나의 출발지와 목적지를 보여준다.
- 이재민 규모, 성장 도시, 붕괴/긴장 도시 수를 보여준다.

> “Worker는 사람 한 명씩이 아니라 청년·생산연령·고령 코호트를 계산합니다. 화면은 영향이 큰 이동만 보여줍니다. 숫자는 정직하게 계산하고, 장면은 읽기 쉽게 압축한 겁니다.”

서로 다른 취약성을 가진 두 국가를 빠르게 비교한다.

- 준비된 후반 상태에서 마지막 턴을 진행한다.

## 6. 예상 질문과 답변

### “실제 기후 예측인가요?”

아닙니다. IPCC·WMO·NASA 자료에서 인과 방향과 현재 문제를 참고했지만, 수치와 국가 전망은 재미와 가독성을 위해 단순화한 게임 시나리오입니다. 실제 정책 결정에 사용할 수 없습니다.

### “5,000셀인데 왜 대규모 시뮬레이션인가요?”

MVP에서 필요한 것은 셀 수 자랑이 아니라 정책→자원→이주의 연쇄가 실제로 돌아가는 것입니다. 5,000셀로 코어 재미와 성능을 검증한 뒤 20,000셀, WebGPU Compute 100,000셀 순으로 확장합니다.

### “Babylon.js를 선택한 이유는?”

3D 표시만이 아니라 인스턴싱, 파티클, 장면 관리와 WebGPU 경로가 필요한 게임이기 때문입니다. WebGPU를 지원하지 않는 환경은 WebGL2로 폴백합니다.

### “AI가 전부 만든 게임인가요?”

제작자가 문제 정의, 핵심 경험, 기술 선택, 범위와 품질 판단을 맡았습니다. Codex는 이를 코드와 문서로 구체화하고, 병렬 구현·테스트·통합을 가속했습니다. 사람의 디렉션과 검증 과정은 commit 및 협업 기록으로 공개합니다.

### “게임에서 자유도는 어디에 있나요?”

매 턴 감축·적응·자연·정의를 아우르는 13개 정책 중 최대 2개를 조합하고 사건의 비용을 선택합니다. 같은 온도 목표라도 예산, 신뢰, 생태계, 이주 수용 능력에 따라 경로와 결말이 달라집니다. 반복 투자에는 체감 효과가 있어 고정된 정답 덱을 방지합니다.

### “리더보드는 실제 온라인 순위인가요?”

현재 심사 빌드는 서버 장애 없이 플레이를 보장하기 위한 `LOCAL DEMO`입니다. 내장 샘플과 이 브라우저의 완료 기록을 생존 연도, 종합 점수 순으로 비교합니다. 공유 Cloudflare Worker+D1은 저장소에 구현·테스트되어 있지만 외부 배포하지 않았습니다. 배포 시에도 클라이언트 점수를 그대로 믿지 않고 version·scenario·seed·턴별 선택 로그를 2026년부터 완전히 재실행해 검증합니다. Go/PostgreSQL이나 Redis는 D1의 실제 운영 한계가 측정될 때만 검토합니다.
